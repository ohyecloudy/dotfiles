# 독자 프로필 (정본)

`code-tour`, `walkthrough`, `warm-start`가 공유하는 독자 숙련도 규칙. 같은 코드라도 독자가 모르는 언어 버전·프레임워크 위에 있으면 관용구가 소음으로 보인다 - 무엇을 설명할지를 독자 기준으로 정하려고 둔다. 세 스킬이 같은 기록을 읽어야 한 번 답한 것을 다시 묻지 않는다.

## 기록 형식

`~/.claude/CLAUDE.local.md`(전역 `CLAUDE.md`가 `@`로 로드)에 두 줄로 둔다.

```
- 주력 언어: <X> <익숙한 버전>
- 프레임워크 숙련도: <이름> <낮음|보통|높음>, <이름> <낮음|보통|높음>
```

예: `- 주력 언어: C++ 11`, `- 프레임워크 숙련도: Unreal Engine 낮음, SwiftUI 보통`

## 대상 판정

대상(독자가 읽을 코드) 쪽에서 아래를 판정한다.

- **대상 언어와 버전**: 확장자·빌드 파일로 언어를, 빌드 설정(`CMAKE_CXX_STANDARD`, `-std=`, `SWIFT_VERSION`, `swift-tools-version`, `tsconfig` `target` 등)으로 버전·표준을 찾는다. 없으면 코드에 쓰인 기능으로 하한을 추정하고 추정임을 밝힌다.
- **대상 프레임워크**: 코드가 기대는 프레임워크·엔진·라이브러리 중 **읽는 방식을 바꾸는 것**만(import·빌드 파일·매크로로 판정). 고유 매크로·코드 생성, 수명·메모리 관리, 실행·갱신 모델, 리플렉션을 강요하는 것 - 예: Unreal Engine, SwiftUI, SwiftData, React. 함수 몇 개 부르는 유틸 라이브러리는 제외.

## 묻기와 저장

- 빠진 것만 **한 번에 모아** 묻는다. 이미 기록된 것은 다시 묻지 않는다.
  - 주력 언어가 없다
  - 주력 언어가 대상 언어와 같은데 버전이 없다
  - 대상 프레임워크의 숙련도가 없다
- 답을 `~/.claude/CLAUDE.local.md`에 반영한다(파일이 없으면 만든다). 프레임워크는 기존 줄에 병합해 줄 하나를 유지한다.
- 묻기 전 컨텍스트에 이미 로드된 내용부터 본다 - 파일을 다시 읽을 필요는 대개 없다.

## 낯선 영역

프로필과 대상을 비교해 **독자에게 낯선 영역**을 정한다. 각 스킬은 이 영역을 설명 대상으로 쓰고, 분량·위치는 스킬이 정한다.

- **언어**
  - 주력 언어와 대상 언어가 다르면: 주력 언어에 직접 대응이 없거나 의미가 다른 문법·의미론.
  - 같고 대상 버전이 더 새로우면: 독자 버전 이후 도입된 기능 중 코드에 실제 쓰인 것(예: C++11 독자에게 C++17의 structured binding, `std::optional`, `if constexpr`, CTAD). 독자 버전에서 같은 일을 하던 방식을 함께 댄다(structured binding ≈ `std::tie`).
  - 같고 독자 버전 이상이면: 없음.
- **프레임워크** (숙련도별)
  - 낮음: 기반부터 - 매크로와 그것이 생성하는 것, 객체 수명·메모리 모델, 실행·갱신 루프, 모듈·빌드 구조(예: Unreal이면 `UCLASS`/`UPROPERTY` 리플렉션과 GC 참조, `UObject` 수명, 액터·컴포넌트 틱, `.Build.cs` 모듈). 코드베이스에 흔한 관용구여도 포함한다.
  - 보통: 덜 흔한 기능과 함정만.
  - 높음: 없음. 프레임워크 관용과 다르게 쓴 곳은 설명이 아니라 설계 관찰 대상이다.

프로필에 없는 것을 추측해 채우지 않는다 - 판정 근거는 기록된 프로필과 코드에서 확인한 대상뿐이다.
