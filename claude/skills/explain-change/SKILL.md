# Explain Change

하나의 코드 변경을 읽고 **무엇이 어떻게 바뀌었는지** 구조화된 데이터(JSON)로 설명한다. `walkthrough`(사람 검토용 워크스루), `warm-start`(하루치 CL 요약) 같은 상위 스킬이 이 코어를 호출해 자기 문서를 채운다. diff만 보지 않고 **코드베이스를 탐색**해 diff에 안 담긴 영향 범위·선례까지 복원하는 것이 이 스킬의 존재 이유다.

이 스킬은 **파일을 쓰지 않는다.** JSON을 반환할 뿐, 렌더(org 등)와 저장은 호출자 몫이다.

**분담 원칙**: diff와 코드베이스로 알 수 있는 것은 코어가 낸다. 세션에서만 아는 "왜"(대안을 왜 골랐나 등)와 판정("사람 판단 필요")은 호출자 몫이다.

## 경계

- **결함·버그 탐지는 하지 않는다.** null 역참조, 경계 처리 누락, 성능·스레드 리스크 같은 판정은 이 스킬 밖이다. 그건 호출자나 `/code-review`가 한다.
- 이 스킬은 *설명*한다. 확증 못 한 것은 `inferred` 근거로 표시해 호출자에게 넘긴다("사람 판단 필요"는 호출자가 이 태그로 만든다).
- **평가어는 쓰지 않는다.** "얕다", "개선 필요"는 설계 비판이라 경계 밖이다. 위치·형태·영향의 **사실 서술만** 한다(`codebase-design`의 위치·형태 어휘 참조, 평가는 배제).

## 입력

호출자가 아래 중 하나를 넘긴다.

1. **커밋 hash 또는 범위** + 저장소 위치 → 저장소에서 `git show <hash>` / `git diff <range>`로 diff를 직접 확보한다. 큰 변경도 truncation 없이 전량 확보한다.
2. **diff 텍스트** (+ 가능하면 저장소 위치) → 그대로 분석 소스로 쓴다. 저장소 위치가 있으면 탐색 보강에 쓴다.

호출자는 선택적으로 **원하는 다이어그램 종류**(`module`/`class`/`sequence`의 부분집합)를 함께 지정할 수 있다. 지정된 종류만 §4에서 탐색·생성하고, **지정이 없으면 다이어그램을 만들지 않는다**(안 그릴 걸 탐색하면 낭비 - 탐색 비용을 요청 범위에 맞춘다).

한 번의 호출은 **한 변경 단위**(커밋 1개 / 범위 1개 / diff 1건)를 다룬다. 여러 CL·커밋을 가로지르는 묶기는 호출자가 결과를 모아서 한다.

입력이 cp949 등 비 utf-8이면 **utf-8로 변환해** 처리한다. 반환 JSON은 항상 utf-8이다.

## 절차

### 1. diff·통계 확보

입력이 hash/범위면 저장소 위치에서 git으로 diff를 뜬다(diff 텍스트면 그대로). binary는 건너뛴다. 동시에 변경 규모(`stat`: 파일 수, 추가/삭제 라인)를 `git show --numstat` 등으로 확보한다.

### 2. 논리 단위 묶기

**이 입력 diff 안에서만** subsystem/기능 단위로 묶는다(예: "에셋 검증 커맨드렛"). 파일 경계가 아니라 아키텍처 경계로 묶는다. 대개 1~수 개. 여기서 **뺀 부분**(기계적 반복, 포매팅, 자동 생성 등)은 `omitted`에 기록한다.

### 3. 코드베이스 탐색 보강

변경된 **공개 심볼**(함수·타입·시그니처·상수)을 diff에서 식별하고, Grep/Read/Glob와 git(read-only)으로 조사한다.

- **영향 범위(`impact`)**: 그 심볼의 참조처·호출부. diff엔 없고 탐색으로만 복원된다.
- **사전 지식(`prerequisites`)**: 이 코드베이스에 **선례 없는** 라이브러리·패턴·알고리즘. grep으로 선례 유무를 확인해 판정한다(선례 있으면 사전 지식 아님). "무엇"과 "등장 위치"까지 사실로 채우고, "왜 이걸 골랐나·대안"은 호출자 보강 몫으로 남긴다.
- 정의·관련 모듈: 아키텍처 관찰의 근거.

### 4. 다이어그램 구성 (요청된 종류만)

입력에서 다이어그램 종류가 지정됐을 때만 수행한다. **변경 중심 + 2홉 이웃**을 대상으로, 요청된 종류의 mermaid 소스를 만든다(§3의 `impact` 탐색을 재사용해 2홉으로 확장한다).

- **module**(`flowchart`): 변경이 닿은 모듈과 그 2홉 이웃, include/import/참조 엣지.
- **class**(`classDiagram`): 변경이 닿은 클래스와 2홉 이웃, 상속/합성/연관 엣지.
- **sequence**(`sequenceDiagram`): diff와 탐색으로 복원한 호출 순서.

규율:

- **엣지 라벨 = 관계 동사.** 무라벨 엣지는 "뭔가 연결돼 있다"까지만 읽힌다. `sends`·`creates`·`observes`처럼 무엇을 하는 관계인지 적는다.
- **근거는 선 모양이 아니라 라벨로 표시한다.** 추정 엣지는 라벨 앞에 `?`를 붙인다(`?sends`). 라벨 채널을 쓰는 이유는 선 모양에 이미 관계 의미가 걸려 있어서다 - class의 `..>`는 UML 의존, sequence의 `-->>`는 응답 메시지라, 점선을 추정 뜻으로 겹쳐 쓰면 확인된 관계까지 추정으로 읽힌다. `basis` 규율을 그대로 상속한다 - grep/read로 확인한 것만 무표시.
  - flowchart: `PCM -->|sends| Sel` / 추정은 `PCM -->|?sends| Sel`
  - class: `Workout ..> Selection : creates` / 추정은 `: ?creates`
  - sequence: `CV ->> WCM: chooseExercise(offset:)` / 추정은 `: ?chooseExercise(offset:)`
- **캡션 범례는 조건부.** 추정 엣지가 하나라도 있을 때만 "?=추정"을 넣는다. 추정이 0이면 범례를 쓰지 않는다 - 늘 붙이면 오독을 부른다.
- **추정이 전체 엣지의 1/3을 넘으면 그대로 내지 않는다.** grep/read로 더 확인하거나, 확인 못 한 엣지는 빼고 캡션에 "관계 N개 미확인"을 적는다. 절반이 추정인 그림은 리뷰어에게 노이즈다.
- **노드 라벨 = 식별자 + 역할 한 줄.** 식별자만 두지 않는다. `<br/>`로 역할을 붙여 그림만 보고도 각 노드가 왜 있는지 알 수 있게 한다.
  - 역할은 이름을 풀어 쓴 게 아니라 **책임 서술**. 예) `Sel["libre08Shared/WatchWorkoutSelection<br/>워치 운동 선택 정보를 공유하는 모듈"]`
  - sequence는 `participant Sel as libre08Shared/WatchWorkoutSelection<br/>워치 운동 선택 정보 공유`, class는 `class Foo["Foo<br/>역할"]`.
- **변경 노드는 하이라이트**(mermaid `classDef changed ...` + `class <Id> changed`)로 이웃과 구분한다. `class` 지정은 노드 하나당 한 줄 - 쉼표로 여러 식별자를 묶지 않는다(`class A,B changed`는 무효 구문).
- **노드 상한 ~15.** 넘으면 가장 먼 홉·변경과 무관한 잎 노드부터 가지치기하고 캡션에 "외 N개 생략"을 적는다.
- **유효 엣지가 0이면 그 종류는 생략한다**(빈 다이어그램 금지). 코드가 아니거나 관계가 없는 변경은 다이어그램이 안 나올 수 있다.

### 5. 읽는 순서

이 변경을 이해하려면 어느 파일부터 읽어야 하는지(`reading_order`)를 의존·이해 순서로 정한다.

### 6. 출력

아래 JSON을 반환한다. 서브에이전트로 위임돼 호출되면 **최종 반환 텍스트 전체가 이 JSON**이어야 한다(설명 산문을 덧붙이지 않는다).

```json
{
  "stat": { "files": 3, "insertions": 40, "deletions": 12 },
  "units": [
    {
      "title": "논리 단위 제목(한국어)",
      "summary":      [{ "text": "핵심 변경 한 줄", "basis": "diff|codebase|inferred" }],
      "architecture": [{ "text": "위치·형태 서술 한 줄", "basis": "diff|codebase|inferred" }],
      "impact":       [{ "symbol": "Foo::Bar", "refs": ["/abs/path.cpp:120"] }],
      "evidence":     [{ "path": "/abs/path.cpp:120", "origin": "diff|codebase", "before": "수정 전 원본 라인(신규 추가면 \"\")", "snippet": "핵심 라인만" }]
    }
  ],
  "prerequisites": [{ "concept": "개념명", "what": "무엇인지 한 줄", "location": "/abs/path.cpp:40" }],
  "reading_order": [{ "path": "/abs/path.cpp:40", "why": "왜 여기부터" }],
  "omitted":       [{ "text": "생략분과 이유" }],
  "diagrams":      [{ "kind": "module|class|sequence", "title": "제목(한국어)", "caption": "무엇을 보는 그림인지 한 줄(추정 엣지 있으면 ?=추정 범례 포함)", "mermaid": "<mermaid 소스>" }]
}
```

`stat`·`prerequisites`·`reading_order`·`omitted`·`diagrams`는 변경 단위 전체 레벨(파일은 논리 단위를 가로지르므로). `units[]`만 논리 단위별이다. `diagrams`는 입력에서 요청된 종류만, 유효 엣지가 있을 때만 채운다(요청 없으면 빈 배열).

## 작성 규칙

- **`basis`(근거 출처)는 필수다.** `diff`=diff 확증, `codebase`=탐색 확인, `inferred`=추정. 추정을 확증처럼 쓰지 않는다. 호출자가 이 태그로 신뢰도를 판단하고 "사람 판단 필요"를 만든다.
- **`impact`·`prerequisites`는 탐색으로 확인한 것만.** 못 찾았거나 해당 없으면 빈 배열. 추측으로 채우지 않는다. 특히 `prerequisites`는 grep으로 선례 없음을 확인한 것만.
- **근거 코드(`evidence`)는 최소 라인만.** 함수·hunk 통째 복붙 금지. 논리 단위당 20줄 이내(`before`+`snippet` 합산), 판단을 뒷받침하는 줄만. `origin`으로 diff hunk인지 주변 코드인지 구분한다.
- **`before`는 기존 라인을 고친 evidence에만 채운다.** 같은 diff hunk의 삭제(`-`) 라인에서 그대로 뽑는다(추가 git 조회 불필요) - 순수 신규 추가 라인이면 `before: ""`. diff 형식이라도 원본 hunk 그대로 덤프하지 않고 최소 대비 라인만.
- **경로는 어디에 쓰든 항상 `절대경로:단일라인`.** `/abs/path/foo.cpp:42` 형식. 상대경로(`foo.cpp:42`)·파일명만·라인 범위(`:42-50`)는 emacs ffap/compilation-mode가 점프 못 하므로 금지. `summary`·`architecture` 같은 산문 text에 인라인으로 넣어도 되지만, 그때도 반드시 절대경로:단일라인이어야 한다(절대경로면 문장 중간이어도 점프된다). `impact.refs`·`evidence.path`·`prerequisites.location`·`reading_order.path`도 동일.
- **`text`는 한 항목 = 한 줄.** 산문 문단으로 뭉치지 않는다.
- **다이어그램(`diagrams`)은 요청된 종류만, 유효 엣지가 있을 때만 낸다.** 노드 라벨은 실제 코드 식별자(클래스·파일·네임스페이스) + `<br/>` + 역할 한 줄이며, `["라벨"]`로 감싸 **구문상 유효한 mermaid**를 보장한다(`::`·`<>` 등 특수문자 포함 시에도 동일). 엣지에는 관계 동사 라벨을 달고, 추정은 라벨 앞 `?`로 표시한다(선 모양은 관계 의미 전용). 변경 노드는 하이라이트. 노드 상한 ~15, 초과분은 `caption`에 "외 N개 생략"으로 명시한다. `mermaid`엔 소스만 담고 org `#+begin_src` 래핑·`:file`·`:width`는 호출자 몫이다.
- 설명·제목은 한국어. **모든 출력은 utf-8**(입력이 cp949 등이면 변환해 처리).
- 변경이 없거나 코드가 아니면 `units: []`와 빈 배열들을 반환한다.
