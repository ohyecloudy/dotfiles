# Explain Change

하나의 코드 변경을 읽고 **무엇이 어떻게 바뀌었는지** 구조화된 데이터(JSON)로 설명한다. `walkthrough`(사람 검토용 워크스루), `warm-start`(하루치 CL 요약) 같은 상위 스킬이 이 코어를 호출해 자기 문서를 채운다. diff만 보지 않고 **코드베이스를 탐색**해 diff에 안 담긴 영향 범위까지 복원하는 것이 이 스킬의 존재 이유다.

이 스킬은 **파일을 쓰지 않는다.** JSON을 반환할 뿐, 렌더(org 등)와 저장은 호출자 몫이다.

## 경계

- **결함·버그 탐지는 하지 않는다.** null 역참조, 경계 처리 누락, 성능·스레드 리스크 같은 판정은 이 스킬 밖이다. 그건 호출자(예: `warm-start`의 우려 사항 층)나 `/code-review`가 한다.
- 이 스킬은 *설명*한다. 판정이 필요한 것은 `inferred` 근거로 표시해 호출자에게 넘긴다.
- **평가어는 쓰지 않는다.** "얕다", "깊게 만들 수 있다", "개선 필요"는 설계 비판이라 경계 밖이다. 위치·형태·영향의 **사실 서술만** 한다(`codebase-design`의 위치·형태 어휘를 참조하되 평가는 배제).

## 입력

호출자가 아래 중 하나를 넘긴다.

1. **커밋 hash 또는 범위** + 저장소 위치 → 저장소에서 `git show <hash>` / `git diff <range>`로 diff를 직접 확보한다. 큰 변경도 truncation 없이 전량 확보한다.
2. **diff 텍스트** (+ 가능하면 저장소 위치) → 그대로 분석 소스로 쓴다. 저장소 위치가 있으면 탐색 보강에 쓴다.

한 번의 호출은 **한 변경 단위**(커밋 1개 / 범위 1개 / diff 1건)를 다룬다. 여러 CL·커밋을 가로지르는 묶기는 호출자가 결과를 모아서 한다.

## 절차

### 1. diff 확보

입력이 hash/범위면 저장소 위치에서 git으로 diff를 뜬다. diff 텍스트면 그대로 쓴다. binary는 건너뛴다.

### 2. 논리 단위 묶기

**이 입력 diff 안에서만** subsystem/기능 단위로 묶는다(예: "에셋 검증 커맨드렛", "빌드 스크립트"). 파일 경계가 아니라 아키텍처 경계로 묶는다. 대개 1~수 개.

### 3. 코드베이스 탐색 보강

변경된 **공개 심볼**(함수·타입·시그니처·상수)을 diff에서 식별하고, Grep/Read/Glob와 git(read-only)으로 다음을 조사한다.

- **영향 범위(impact)**: 그 심볼의 참조처·호출부. diff엔 없고 탐색으로만 복원된다.
- 정의·관련 모듈: 아키텍처 관찰의 근거.

탐색은 **설명 품질을 높이는 수단**이다. 출력 범위(요약·아키텍처·근거)를 넓히지 않는다. 탐색 중 결함이 눈에 띄어도 판정하지 않는다.

### 4. 출력

아래 JSON을 반환한다. 서브에이전트로 위임돼 호출되면 **최종 반환 텍스트 전체가 이 JSON**이어야 한다(설명 산문을 덧붙이지 않는다).

```json
{
  "units": [
    {
      "title": "논리 단위 제목(한국어)",
      "summary":      [{ "text": "핵심 변경 한 줄", "basis": "diff|codebase|inferred" }],
      "architecture": [{ "text": "위치·형태 서술 한 줄", "basis": "diff|codebase|inferred" }],
      "impact":       [{ "symbol": "Foo::Bar", "refs": ["/abs/path.cpp:120"] }],
      "evidence":     [{ "path": "/abs/path.cpp", "lines": "120-127", "origin": "diff|codebase", "snippet": "핵심 라인만" }]
    }
  ]
}
```

## 작성 규칙

- **`basis`(근거 출처)는 필수다.** `diff`=diff로 확증, `codebase`=탐색으로 확인, `inferred`=추정. 추정을 확증처럼 쓰지 않는다. 호출자가 이 태그로 신뢰도를 판단하고 "단정 금지" 규율을 지킨다.
- **`impact`는 탐색으로 복원한 참조처만.** 못 찾았으면 빈 배열. 추측으로 채우지 않는다.
- **근거 코드(`evidence`)는 최소 라인만.** 함수·hunk 통째 복붙 금지. 논리 단위당 20줄 이내, 판단을 뒷받침하는 줄만. `origin`으로 diff hunk인지 주변 코드인지 구분한다.
- **경로는 절대 경로 + 라인 번호.** `foo.cpp:42`가 아니라 `/abs/path/foo.cpp:42`. `impact.refs`, `evidence.path` 모두 해당.
- **`text`는 한 항목 = 한 줄.** 산문 문단으로 뭉치지 않는다.
- 설명·제목은 한국어. cp949에서 온 한글은 그대로 쓴다.
- 변경이 없거나 코드가 아니면 `units: []`를 반환한다.
