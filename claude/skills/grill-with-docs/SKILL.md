`/domain-modeling` 스킬을 사용하면서 `/grilling` 세션을 진행한다.

## 산출물 경계

이 스킬이 만드는 문서는 `domain-modeling`이 지시하는 둘뿐이다.

- `CONTEXT.org` - 용어집
- `docs/adr/` - ADR

**spec·티켓은 절대 쓰지 마라.** 설계가 아무리 굳었어도, 세션 중에 산출물 목록으로 제안해 승인을 받았어도 마찬가지다. 그 문서들에는 각자의 스킬(`/to-spec`, `/to-tickets`)이 있고, 언제 호출할지는 사용자가 정한다.

## 세션 종료

확정된 결정을 대화에 정리하고 멈춘다. `/to-spec`은 대화 맥락을 그대로 읽어 합성하므로 별도 인계 문서를 만들 필요가 없다.

정리 뒤 다음 스킬을 *제안*만 한다.

- 설계가 여물었으면(문제·해결책·주요 구현 결정·범위 밖이 모두 확정) → `/to-spec` 제안
- 아직 열린 갈래가 남았으면 → 무엇이 미해결인지 밝히고 제안하지 않는다

제안은 한 줄로 족하다. 예) "설계가 굳었다. spec으로 넘기려면 `/to-spec`을 호출하라."

제안한 스킬을 직접 실행하지 마라. 사용자가 다음 턴에 호출한다.
