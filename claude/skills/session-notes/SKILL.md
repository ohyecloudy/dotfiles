# Session Notes

현재 세션에서 한 일과 결과를 **빠짐없이** 모은 재료 노트를 만든다. 용도는 둘이다.

- 다른 사람에게 줄 이슈를 사용자가 직접 쓸 때의 재료. 항목을 이슈에 옮기면 사용자가 `TODO` -> `DONE`으로 바꿔, 빠진 항목을 기계적으로 찾는다.
- 세션을 정리해 두고 나중에 이어서 작업. 사용자가 노트 경로를 새 세션의 AI에게 넘긴다.

## 경계

- **이슈 초안이 아니다.** 제목, 배경, 할 일 같은 이슈 형식으로 쓰지 않는다. 사실만 분류해 나열한다.
- **현재 세션만** 본다. 다른 세션 jsonl은 찾지도 읽지도 않는다.
- 노트는 **한 번만** 쓴다. 이전 노트를 찾거나 갱신하지 않는다.
- 빼는 것: 관련 커밋, 파일 목록, 사용자 취향, 포매팅 지시(예: "두괄식 선호", "백틱 대신 `=...=`"). 스킬이나 설정을 고치는 지시는 일을 받는 사람에게 필요 없다. 단, 그 지시로 **끝난 작업**은 `끝난 일`에 들어간다.
- `handoff`와 다른 점: handoff는 다른 산출물에 있는 내용을 빼고 링크만 남긴다. 여기는 관련 문서(poc.org 등)의 내용도 재료로 뽑아 한 노트에 모은다.

## 절차

### 1. 입력 확정

- 세션 id: `${CLAUDE_SESSION_ID}`
  - 치환이 안 돼 글자 그대로 남아 있으면 스크립트가 `~/.claude/projects/*/*.jsonl` 중 mtime 최신(지금 기록 중인 파일)을 쓴다. 스크립트가 출력한 `transcript:` 경로가 이 세션이 맞는지 마지막 사용자 발언으로 확인한다.
- 관련 문서
  - 인자가 있으면 그 경로를 쓴다.
  - 없으면 탐지 모드를 돌려 목록을 보여주고, 사용자에게 번호로 고르게 한다(없음 선택 가능). 스킬, 설정 파일처럼 일의 재료가 아닌 문서는 사용자가 뺀다.

`$HOME_W`는 홈 디렉터리의 python용 경로. Windows Git Bash에서는 `HOME_W=$(cygpath -m ~)`(예: `C:/Users/<user>`) - `~/...`를 그대로 넘기면 MSYS 경로 변환이 어긋나 `C:/c/Users/...`가 된다. macOS/Linux는 `HOME_W=$HOME`. `PY=$(command -v python3 || command -v python)` - macOS에는 `python` 명령이 없을 수 있다. `-X utf8`은 Windows에서 한글 출력이 cp949로 깨지지 않게 한다(`-I`가 `PYTHONIOENCODING` 등 환경 변수를 무시).

```bash
"$PY" -I -X utf8 "$HOME_W/.claude/skills/session-notes/extract_session.py" "${CLAUDE_SESSION_ID}" --docs
```

### 2. 대화 추출

```bash
"$PY" -I -X utf8 "$HOME_W/.claude/skills/session-notes/extract_session.py" "${CLAUDE_SESSION_ID}" "<Temp>/session-notes-<세션 id 8자>"
```

- `<Temp>`는 Windows면 `C:/Users/<user>/AppData/Local/Temp`처럼 python이 읽을 수 있는 경로.
- 출력: `meta.txt`(jsonl 경로, 시간 범위)와 `part-<n>.txt`. 파트는 사용자 발언 경계에서 나뉜다.
- 남기는 것: 사용자 발언 전문(`=== U<n> [시각] 사용자`), 에이전트 발언 전문, 도구 호출 한 줄, Bash 결과 앞뒤 15줄, 오류 결과.
- 빼는 것: Read 결과, compact 요약, 메타 항목, 서브에이전트 기록. compact 요약을 빼도 compact 전 원본 발언이 jsonl에 그대로 있어 손실이 없다.

### 3. 항목 추출 (서브에이전트)

Agent 도구로 `general-purpose` 서브에이전트를 **병렬**로 띄운다. 각각 [extract-worker.md](extract-worker.md) 절차를 따른다.

- 대화 파트마다 1개: 프롬프트에 extract-worker.md 절대 경로, 파트 파일 절대 경로, 세션 id 8자, 파트 번호/전체 파트 수.
- 관련 문서마다 1개: extract-worker.md 절대 경로, 문서 절대 경로.
- 메인이 원문을 직접 읽지 않는 이유: 파트 하나가 수만 토큰이라 메인 컨텍스트가 넘친다. 한 worker가 한 덩어리를 끝까지 읽어야 빠짐이 줄어든다.

### 4. 병합 (메인)

- **누락 재확인**: worker가 보고한 "항목 0개 발언"마다 파트 파일에서 그 `U<n>` 구간을 Read로 다시 본다. 단순 동의("yes", "ㅇㅇ")는 바로 앞 에이전트 제안을 확정한 것이라, 그 제안이 `결정`이나 `끝난 일`로 잡혔는지 확인한다. 빠졌으면 추가한다.
- **겹침**: 같은 사실이면 항목 하나로 합치고 출처를 모두 적는다.
- **충돌**: 같은 주제인데 값이나 판단이 다르면(예: poc.org 수치와 이후 대화에서 다시 잰 값, 번복한 결정) 항목 하나에 시간 순서로 모두 적고 heading에 `:충돌:` 태그. **어느 쪽이 맞는지 고르지 않는다** - 나중 대화가 가정을 바꾼 질문일 수 있다.
  - 사용자가 명시적으로 번복한 결정("번복한다", "취소")도 `:충돌:`로 두 값을 남긴다. 번복 사실 자체가 이슈 재료다.
- **분류 경계**
  - `남은 일`: 이미 하기로 정했는데 안 한 작업. "나중에", "확인 못 한 것", "안 돌렸음".
  - `미해결`: 판단이나 확인이 필요한 질문. 할지 말지부터 정해야 하는 것.
  - `작업 상태`: git으로 다시 확인할 수 없는 흔적만. push 안 한 커밋, 커밋 안 하는 외부 문서의 수정, 백업 파일, Temp 스크립트, 실행하지 않은 검증 단계.
- **끝난 일 단위**: 요청 하나, 커밋 하나가 아니라 결과 단위로 묶는다. 같은 결과를 위한 작은 후속 요청(오타, 링크 수정)은 그 결과에 합친다.

### 5. 저장

`~/session-notes/YYYY-MM-DD-HHMM-<slug>.org`에 쓴다(`<slug>` = 세션 주제 kebab). 디렉터리가 없으면 만든다. 커밋하지 않는다.

### 6. 포매팅

- 본문은 [org-writing.md](../shared/org-writing.md) 규칙.
- [org-formatting.md](../shared/org-formatting.md)의 emacs 정렬을 돌린다. 분류 heading의 `[/]` 쿠키 개수가 여기서 채워진다.

### 7. 보고

- 노트 절대 경로
- 분류별 항목 수, `:충돌:` 항목 수
- 누락 재확인에서 추가한 항목 수

## 템플릿

```org
#+title: <세션 주제>

- 세션: <세션 id 8자> <시작 시각> ~ <끝 시각>
- 대화 원본: [[file:<jsonl 절대 경로>][<세션 id 8자>.jsonl]]
- 관련 문서
  + [[file:<절대 경로>][<파일 이름>]]

* 끝난 일 [/]

** TODO <결과 한 줄>

   - 이유: <왜 했나 한 줄>
   - 출처
     + 대화 <id 8자> <HH:MM>, 사용자
       - "<원문 짧은 인용>"

* 결정 [/]

** TODO <결정 한 줄>

   - 출처
     + [[file:<문서 절대 경로>::*<heading>][<파일 이름> - <heading>]]
     + 대화 <id 8자> <HH:MM>, 에이전트 제안 -> <HH:MM> 사용자 동의
       - "<원문 짧은 인용>"

** TODO <주제> :충돌:

   - <HH:MM> <값 또는 판단 1>
     + 출처: 대화 <id 8자> <HH:MM>, 사용자
   - <HH:MM> <값 또는 판단 2>
     + 출처: 대화 <id 8자> <HH:MM>, 사용자

* 남은 일 [/]
* 미해결 [/]
* 제약/주의점 [/]
* 수치/측정 결과 [/]

** TODO <지표>: <값>

   - 조건: <환경, 명령, 범위>
   - 출처
     + ...

* 버린 방식과 이유 [/]
* 범위 밖 [/]

* 작업 상태

- <흔적 한 줄> (TODO 아님)
```

- 분류 순서는 고정. 항목이 없는 분류는 heading 아래 `- 없음` 한 줄. 빈 분류를 지우지 않는 이유: 빠진 것인지 없는 것인지 구분하려고.
- 맨 위 메타 bullet 뒤에 요약 줄을 넣지 않는다. 첫 분류부터 본문이다.
- 출처 형식
  - 대화: `대화 <세션 id 8자> <HH:MM>, <사용자 | 에이전트>` + 원문 짧은 인용. 날짜가 세션 시작일과 다르면 `MM-DD HH:MM`.
  - **에이전트 발언과 사용자 동의를 구분한다.** 에이전트가 "확인함"이라고 쓴 것만으로는 사용자가 확인한 것이 아니다. 사용자 동의가 있으면 `에이전트 제안 -> 사용자 동의`로 둘 다 적는다.
  - 문서: 절대 경로 `[[file:<경로>::*<heading>][...]]`. 노트가 `~/session-notes/`에 있어 상대 경로를 쓸 수 없다.
- 이어받는 AI가 출처 인용만으로 부족하면 맨 위 `대화 원본` jsonl을 시각으로 grep한다.
