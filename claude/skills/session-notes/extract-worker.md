# session-notes 추출 worker

`/session-notes` 메인이 대화 파트 하나 또는 관련 문서 하나에서 항목을 뽑게 맡기는 서브에이전트 절차. 원문은 크므로 메인 컨텍스트에 싣지 않고 여기서 끝까지 읽는다. 파일을 쓰지 않고 결과만 돌려준다.

## 입력 (메인 프롬프트)

- 대화 파트: 파트 파일 절대 경로, 세션 id 8자, 파트 번호/전체 파트 수
- 또는 관련 문서: 문서 절대 경로

**사용자에게 묻지 않는다.**

## 절차

1. 파일을 **처음부터 끝까지** Read한다. 한 번에 안 읽히면 offset을 옮겨 끝까지 읽는다. 일부만 읽고 추출하지 않는다.
2. 아래 분류로 항목을 뽑는다. 한 항목 = 사실 하나.
   - `끝난 일`: 실제로 완료된 결과. 결과 단위로 묶고 왜 했는지 한 줄을 붙인다. 시도만 하고 되돌린 것은 `버린 방식과 이유`로.
   - `결정`: 합의하거나 확정한 것. 에이전트 제안에 사용자가 동의("yes", "ㅇㅇ", "추천대로")한 경우 포함.
   - `남은 일`: 하기로 했는데 안 한 작업. "나중에", "확인 못 한 것", "안 돌렸음".
   - `미해결`: 판단이나 확인이 필요한 질문.
   - `제약/주의점`: 발견한 함정, 지켜야 하는 조건. 예) 파일 줄 끝 CRLF 유지, 특정 도구 호출이 실패하는 조건과 우회법.
   - `수치/측정 결과`: 값 + 측정 조건(환경, 명령, 범위). 조건이 원문에 없으면 "조건 기록 없음".
   - `버린 방식과 이유`
   - `범위 밖`: 일부러 하지 않기로 한 것.
   - `작업 상태`: git으로 다시 확인할 수 없는 흔적. push 안 한 커밋, 커밋 안 하는 문서의 수정, 백업 파일, Temp 스크립트, 실행하지 않은 검증.
3. 뽑지 않는 것: 관련 커밋/파일 목록, 사용자 취향, 포매팅 지시 자체. 단, 그 지시로 끝난 작업은 `끝난 일`.
4. 같은 주제의 값이나 판단이 파일 안에서 바뀌면(번복, 재측정) 하나로 합치지 말고 시각과 함께 각각 적고 `충돌 후보`로 표시한다. 어느 쪽이 맞는지 고르지 않는다.
5. 출처
   - 대화: `대화 <id 8자> <HH:MM>, <사용자 | 에이전트>` + 원문 짧은 인용(한 줄). 에이전트 발언과 사용자 동의를 구분한다 - 에이전트가 "확인함"이라고 쓴 것은 에이전트 출처다.
   - 문서: `<절대 경로>::*<heading 전체 텍스트>`
6. 대화 파트면 사용자 발언(`=== U<n>`)마다 그 발언에서 나온 항목 수를 센다. 0개인 발언은 그대로 보고한다 - 메인이 다시 확인한다.
7. 지어내지 않는다. 원문에 근거가 없으면 항목을 만들지 않는다.

## 반환

```
대상: <파트 <n>/<전체> | 문서 <경로>>
읽은 범위: 처음부터 끝까지 | <중단 위치와 원인>

[끝난 일]
- <내용>
  이유: <한 줄>
  출처: <출처> | "<인용>"
[결정]
- <내용>
  출처: <출처> | "<인용>"
  출처: <출처> | "<인용>"
[남은 일]
...
[작업 상태]
- <내용>
  출처: ...

충돌 후보:
- <주제>: <HH:MM 값1> / <HH:MM 값2>

발언별 항목 수: U<n>=<k>, ...   (문서면 생략)
항목 0개 발언: U<n>, ...         (문서면 생략)
```

항목이 없는 분류는 `[분류]` 다음 줄에 `- 없음`.
