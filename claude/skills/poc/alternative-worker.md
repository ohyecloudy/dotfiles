# PoC 대안 worker

`/poc` 메인이 `구현` 대안 하나를 맡기는 서브에이전트 절차. 메인 컨텍스트를 구현 루프(파일 읽기, 빌드 로그, 재시도)로 채우지 않으려고 분리했다. 상세는 poc.org에 쓰고 메인에는 요약만 돌려준다.

## 입력 (메인 프롬프트)

- poc.org 절대 경로
- 맡은 대안명
- 저장소 위치
- 시작 커밋

합의(검증할 질문, 완료 조건, 비교 축, 범위 밖)는 poc.org `* 합의`에서 직접 읽는다 - 그곳이 정본이다. 다른 대안의 결과는 넘겨받지 않는다.

## 원칙

- **사용자에게 묻지 않는다.** 대화할 수 없다. 모호하면 합의 범위 안에서 가장 보수적인 해석을 고르고 시도 로그에 그 해석을 적는다.
- 맡은 대안 **하나만** 구현한다. 다른 대안의 코드를 건드리지 않는다.
- 속도가 우선이다. TDD·`/code-review`는 하지 않는다. 대신 결론마다 실행 증거를 남긴다.

## 구현

- 현재 작업 트리·현재 브랜치에서 한다. worktree·브랜치를 만들지 않는다.
- **자주 커밋한다.** 동작하는 작은 단계마다 커밋을 나눈다. 커밋 메시지는 `/commit-message`로 쓴다.
- 스테이징은 이 대안이 만든·고친 파일만 경로로 지정한다. 착수 전부터 있던 사용자의 미커밋 변경을 쓸어 담지 않는다.
- push 하지 않는다.
- 코드 주석·커밋 메시지에 저장소 밖 문서를 참조하지 않는다([저장소 텍스트의 문서 참조](../shared/project-docs-storage.md)).

## poc.org 기록

그때그때 poc.org에 직접 추가한다 - 중간에 끊겨도 기록이 남게. 다른 섹션은 건드리지 않는다. 형식은 [SKILL.md](SKILL.md)의 템플릿과 "org 작성 규칙"을 따른다.

- `* 검증 근거`: 결론마다 빌드 성공 + 실행 명령과 출력 요약(수치면 수치 그대로) + 커밋 hash. 항목 앞에 대안명을 붙인다.
- `* 시도 로그`: 접근을 버리거나 대안을 끝낼 때마다 한 줄 - 무엇을 시도 / 왜 버렸나(또는 결과) / 커밋 hash. 버린 접근의 "왜"는 코드에도 커밋에도 남지 않는 trade-off의 핵심 재료다.
- `* 수동 확인 필요`: 사람만 확인할 수 있는 증거(에디터 시각 확인, 실기기 등)는 확인 방법과 함께 남기고 진행한다. "없음" 줄이 있으면 지우고 쓴다.

## 종료 조건

아래 중 하나에 닿으면 멈추고 반환한다.

- 완료 조건 충족 -> `done`
- 가설 반증("이 대안으로는 안 된다"가 실행으로 증명됨) -> `disproved`. 답에 "불가 + 근거"
- 같은 장애(빌드 실패, 가설과 다른 동작 등)에 **접근을 2번 바꿔도** 진전 없음 -> `blocked`. 부분 결론 + 막힌 원인

## 반환

poc.org에 쓴 상세를 반복하지 말고 아래만 반환한다.

```
대안: <대안명>
종료: done | disproved | blocked
답: <한 줄>
실측:
- <비교 축>: <값>
커밋: <첫 커밋>..<마지막 커밋> (없으면 "없음")
수동 확인 필요: 있음 | 없음
```
