# PoC 확인 질문 worker

`/poc` 메인이 `* TODO 확인 질문` 작성을 맡기는 서브에이전트 절차. 체인은 홉마다 코드를 열어 발췌하고 경로 그림을 그려야 해서 탐색량이 크다 - 메인 컨텍스트에 싣지 않으려고 분리했다. poc.org에 직접 쓰고 메인에는 개수만 돌려준다.

## 입력 (메인 프롬프트)

- poc.org 절대 경로
- 저장소 위치
- 낯선 영역 (없으면 생략)

**사용자에게 묻지 않는다.** 확정 못 하는 홉·체인은 버리고 `질문 안 낸 재료`에 사유를 적는다.

## 형식

[walkthrough SKILL.md](../walkthrough/SKILL.md)의 "확인 질문" 규칙과 템플릿을 따른다 - 체인 `**` 본문(출처/배경/출발점), 홉 `*** TODO <n>. <질문>` + `볼 곳`, `**** 힌트` / `**** 답`(결론 + 위치 + 발췌 + 다음 홉), `*** 정리` 그림, 통계 쿠키, `질문 안 낸 재료`. 공통 틀은 [reading-doc.md](../shared/reading-doc.md)의 "확인 질문 공통 틀". 아래는 poc에서 다른 점만.

## poc 차이

- **재료**(우선순위 순). 재료 항목당 체인 최대 1개, 문서당 **최대 4개** - 차면 멈춘다.
  1. `* trade-off` 축 중 대안끼리 값이 갈린 것(표 행 순서). 마지막 홉 = 대안 반사실 - "대안 X였다면 이 경로의 몇 번 홉이 어떻게 바뀌나". 출발 경로는 그 축을 실측한 대안의 코드, 반사실 쪽은 다른 대안의 코드 또는 `** 대안 비교` 그림
  2. `* 사전 지식` 중 `reader-unfamiliar`이고 `등장 위치`가 PoC 코드에 있는 것. 마지막 홉 = 주의점 추적 - "주의점 W가 이 경로의 어느 홉에서 걸리나"
  3. `* 핵심 코드 워크스루` 논리 단위 - 요약이 코드 경로를 압축한 곳. 추적 홉만
- 아키텍처 델타 재료와 `사람 판단 필요` 재료는 없다 - poc 문서에 그 섹션이 없다.
- **`분석만` 대안이 걸린 홉**: 코드가 없으므로 `볼 곳`과 답 `위치`는 `* 시도 로그 - 서브에이전트 기록`의 Explore 근거 위치(실제 코드베이스 위치). 답 결론 끝에 `(분석)`을 붙여 실측과 구분한다. 근거 위치가 없으면 그 홉을 버린다.
- 체인 heading 재료 종류 표기: `trade-off` / `사전 지식` / `워크스루`.
- `질문 안 낸 재료` 사유: `상한` / `확정 불가` / `분석 근거 없음`.
- 그림 `:file` = `./quiz-<체인 순번>.png`(poc.org 옆).
- 코드 발췌 기준은 지금 working tree - PoC 커밋은 이미 끝나 있다.

`* TODO 확인 질문` 밖은 건드리지 않는다. 재료가 하나도 없으면 섹션 본문에 "없음" 한 줄(쿠키·drawer 없이).

## 반환

```
확인 질문: 완료 | 실패(<원인 한 줄>)
체인: <개수>, 질문: <개수>
제외: <개수> (<사유별 개수>)
```
