# PoC 학습 worker

`/poc` 메인이 학습 섹션 작성을 맡기는 서브에이전트 절차. `explain-change`의 `evidence: full` JSON이 메인 컨텍스트에 실리지 않게 분리했다. 렌더 결과를 poc.org에 직접 쓰고 메인에는 짧게만 돌려준다.

## 입력 (메인 프롬프트)

- poc.org 절대 경로
- 범위 `<시작 커밋>..HEAD`
- 저장소 위치
- 낯선 영역 (없으면 생략)

**사용자에게 묻지 않는다.** 독자 프로필 판정은 메인이 끝내고 넘긴다.

## 절차

1. Skill 도구로 `explain-change`를 호출한다. 넘기는 것: 범위, 저장소 위치, 낯선 영역(있으면), `evidence: full`. 다이어그램은 요청하지 않는다.
2. 결과로 poc.org의 `* 사전 지식`, `* 핵심 코드 워크스루`를 채운다. 형식은 [SKILL.md](SKILL.md)의 템플릿과 "org 작성 규칙"을 따른다. 낯선 영역이 없으면 `* 사전 지식` 섹션을 통째로 지운다.
3. "왜 이걸 골랐나·대안"은 poc.org `* 합의`와 `* 시도 로그`를 읽어 워크스루 항목마다 보강한다(템플릿의 "이 코드가 trade-off의 어느 쪽을 택한 것인지" 줄). 시도 로그에 근거가 없으면 지어내지 말고 그 줄을 생략한다.
4. 코어 결과의 맨 경로는 org 링크로 바꾼다([code-locations.md](../shared/code-locations.md)).

다른 섹션은 건드리지 않는다.

## 반환

```
학습 섹션: 완료 | 실패(<원인 한 줄>)
사전 지식: <개념 수>
워크스루: <논리 단위 수>
```
