# Walkthrough

방금 생성된 코드를 **사람이 검토할 수 있도록** 안내하는 문서를 만든다. 코드를 쓴 에이전트가 저자(author), 사용자가 리뷰어(reviewer)다.

## 경계

- **결함·버그 탐지는 하지 않는다.** 그건 `/code-review`, `/simplify` 몫이다. 같은 diff를 두 번 훑어 결론이 엇갈리면 리뷰어만 혼란스럽다.
- 이 스킬은 *설명*한다. 판정이 필요한 것은 직접 판단하지 말고 `사람 판단 필요` 섹션으로 넘긴다.
- 존재 이유는 **코드에 남지 않는 정보**다 - 스펙에 없어 추측으로 채운 지점, 대안 중 하나를 고른 지점. 정적 리뷰로는 복원할 수 없고, 코드를 생성한 에이전트만 안다.

**호출 시점**: 대화 컨텍스트가 살아 있는 동안 호출한다. 세션이 끝나거나 컨텍스트가 압축된 뒤에는 `사람 판단 필요`를 채울 수 없다.

## 프로세스

### 1. 범위 결정

아래 순서로 **처음 맞는 것**을 쓴다.

1. 인자로 범위 지정(커밋 범위 / 경로 / PR 번호) → 그대로
2. 대화 컨텍스트에 이번 세션이 만든 커밋·변경 → 그 합집합
3. uncommitted(staged + working tree)
4. 현재 브랜치가 기본 브랜치와 다름 → `merge-base..HEAD`
5. 전부 실패 → **추측하지 말고 사용자에게 확인**

기본 브랜치에 직접 커밋하는 워크플로에서는 4번이 비므로 2번이 실질적 기본값이다.

컨텍스트 없이 콜드로 호출됐으면 `사람 판단 필요`에 *"세션 컨텍스트 없음 - 추론 불가"*라고 명시한다. 임의로 채우지 않는다.

### 2. 탐색

- `CONTEXT.org`(다중 컨텍스트면 `CONTEXT-MAP.org` → 각 `CONTEXT.org`)가 있으면 읽어 그 용어를 문서 전반에 쓴다.
- 건드리는 영역에 `docs/adr/` ADR이 있으면 찾아 둔다.
- 둘 다 없으면 넘어간다(강제하지 않음). glossary는 **읽기만** 한다 - 갱신은 `domain-modeling` 몫.

### 3. 변경 분석

Skill 도구로 `explain-change`를 호출해 변경을 분석한다. §1에서 정한 범위를 그대로 넘긴다 - 커밋 범위면 hash/범위, uncommitted면 diff 텍스트, 저장소 위치도 함께. **인라인 호출**이라 세션 컨텍스트를 유지한 채 결과를 받는다.

반환 JSON이 다음 문서의 재료다 - `stat`(범위·규모), `units[]`(`summary`/`architecture`/`impact`/`evidence`), `prerequisites`(사전 지식), `reading_order`(읽는 순서), `omitted`(다루지 않은 변경). 코어는 diff·코드베이스로 알 수 있는 것을 위치·형태의 **사실 서술로만** 채운다(`codebase-design` 어휘 참조, 평가·판정 없음). 이 스킬은 코어가 못 내는 것 - `basis: inferred`에서 뽑는 `사람 판단 필요`, 사전 지식의 "왜 이걸 골랐나·대안", 그 밖에 세션에서만 아는 "왜" - 를 세션 컨텍스트로 보강한다.

### 4. 문서 작성

§3의 코어 JSON을 재료로 아래 구조를 채운다. `헤드라인`의 범위·규모는 `stat`, `아키텍처 델타`는 `units[].architecture` + `impact`(호출자가 새로 알아야 할 참조처), `사전 지식`은 `prerequisites`, `읽는 순서`는 `reading_order`, `워크스루`는 `units[].summary`(설명) + `evidence`(근거 코드), `다루지 않은 변경`은 `omitted`로 채운다. `사람 판단 필요`(코어 `basis: inferred`에서)와 사전 지식의 "왜·대안" 등 세션에서만 아는 부분은 이 스킬이 보강한다.

`~/walkthrough/YYYY-MM-DD-HHMM-<slug>.org`에 쓴다(`<slug>` = 변경 주제 kebab). 디렉터리가 없으면 만든다.

```org
#+title: Walkthrough - <한 줄 제목>

* 헤드라인

  - <이번 변경의 정체 한 줄>
  - 범위: <SHA 범위 | uncommitted> - 파일 <N>개, +<A>/-<B>
  - 사전 지식: <목록 | 없음>
  - 사람 판단 필요: <N>건

* 아키텍처 델타

  - <새로 생기거나 사라지거나 이동한 모듈>
  - <인터페이스 변경 - 호출자가 새로 알아야 하는 것>
  - <의존성 방향 변화>
  - <상태·데이터 소유권 이동>
  - 변경 후 데이터 흐름: <한 줄>
  - ADR-<NNN> 준수 - <어느 부분이>        ← 관련 ADR 있을 때만

* 사전 지식(prerequisite)                  ← 해당 없으면 섹션 통째 생략

** <개념명>

   - 무엇: <한 줄>
   - 왜 여기 필요했나: <한 줄>
   - 대안: <한 줄>
   - 주의점: <한 줄>
   - 등장 위치: /abs/path/foo.ts:40

* 읽는 순서

  1. /abs/path/foo.ts:12 - <왜 여기부터>
  2. /abs/path/bar.ts:88 - <왜 그다음>

* 워크스루

** <논리 단위 제목>

   - <설명 한 줄>
   /abs/path/foo.ts:40
   #+begin_src ts
   <근거 라인만>
   #+end_src
   - <설명 한 줄>

* 사람 판단 필요

  - <결정> - 근거: <…>, 대안: <…> → /abs/path/foo.ts:40
                                              ← 없으면 "없음" 한 줄

* 다루지 않은 변경

  - <생략분과 이유>
```

### 5. 포매팅

쓴 뒤 emacs로 org 들여쓰기를 정렬한다.

```bash
emacs -Q --batch --eval '(progn (require (quote org)) (setq org-adapt-indentation t) (let ((dir default-directory)) (dolist (f command-line-args-left) (find-file (expand-file-name f dir)) (org-mode) (org-indent-region (point-min) (point-max)) (save-buffer))))' <생성한 .org 파일들>
```

emacs에서 파일을 열었다 저장한 것과 같은 상태로 만든다 - 헤딩 아래 본문이 별 개수 + 1칸으로 정렬된다. 여러 파일을 한 번에 넘길 수 있다. emacs가 없거나 실패하면 파일은 그대로 두고 사용자에게 그 사실만 알린다.

### 6. 보고

채팅에는 문서 전문을 쏟지 말고 아래만 출력한다.

- 이번 변경의 정체 한 줄
- 아키텍처 델타 핵심 1~2줄
- `사람 판단 필요` 건수
- 생성한 org 파일의 **절대 경로**

## 작성 규칙

- **논리 단위별로 묶는다. 파일별이 아니다.** 파일 경계는 아키텍처 경계와 일치하지 않는다.
- **발췌는 최소 라인만.** hunk나 함수를 통째로 복붙하지 않는다. 설명의 근거가 되는 줄만, 논리 단위당 20줄 이내, 원본 인덴트 유지. 언어가 불명확하면 `#+begin_example`.
- **완전성보다 선별.** 문서 총량 상한은 없지만 리뷰어가 봐야 할 것만 싣는다. 대신 **생략한 것을 `다루지 않은 변경`에 반드시 적는다** - 선별 요약은 *"이게 전부인가?"*에 답하지 못하면 신뢰받지 못한다. 포매팅, 기계적 반복, 자동 생성 파일 등을 한 줄로 묶어 명시한다.
- **코드 위치는 절대 경로 + 라인 번호.** emacs `ffap` 점프용이다. `foo.ts:42`가 아니라 `/abs/path/foo.ts:42`.
- **빈 섹션은 "없음"으로 명시한다.** 섹션을 통째로 지우면 "해당 없음"과 "확인 안 함"이 구분되지 않는다. 예외는 `사전 지식` 하나뿐.
- **사전 지식 판정 기준은 "이 코드베이스에 선례가 없는 것"이다.** `grep`으로 확인할 수 있는 객관적 기준을 쓴다 - 사용자가 알지 모를지 추측하지 않는다.
  - 대상: 라이브러리·프레임워크, 언어 기능, 설계 패턴, 알고리즘, 프로토콜·포맷
  - 제외: 이미 코드베이스에 널린 관용구, 일반 상식
- **ADR과 어긋나면 판정하지 말고 넘긴다.** 준수하면 `아키텍처 델타`에 `ADR-<NNN> 준수`로 서술하고, 어긋나면 결함으로 규정하는 대신 `사람 판단 필요`에 *"ADR-<NNN>과 다르게 구현. 근거: …"*로 적는다.
- **org 렌더**: 한 항목 = 한 bullet, 물리적으로 한 줄(문장 중간 하드 줄바꿈 금지 - 길어도 한 줄, 표시는 emacs soft-wrap). org verbatim(`=...=`) 안에 `=` 문자를 넣지 않는다(구문이 깨진다). 한글 조사가 바로 뒤에 붙는 자리에는 마크업을 쓰지 않는다 - `=Foo=에`는 org가 마크업으로 인식하지 못해 export에서 깨진다. 조사가 붙지 않게 문장을 쓰고, 부득이하면 한 칸 띄운다. 헤딩 아래 본문은 별 개수 + 1칸 들여쓴다(`*` → 2칸, `**` → 3칸).
