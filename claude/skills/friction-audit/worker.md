# friction-audit worker

`/friction-audit` 메인이 세션 묶음 하나의 분석을 맡기는 서브에이전트 절차. 세션 기록에서 **마찰(friction)** 을 찾아 원인과 고칠 곳을 돌려준다. 파일을 쓰지 않고 결과만 반환한다. 사용자에게 묻지 않는다.

## 입력 (메인 프롬프트)

- 세션 디렉터리 절대 경로 목록 - 각각 `part-<n>.txt`
- `signals.jsonl` 절대 경로 - 기계적으로 센 신호. 자기 세션 줄만 참고
- 알려진 패턴 목록 (지난 보고서가 있을 때만) - 지난 발견 항목과 1회성 항목의 heading

## 사용자 환경 (판단 배경)

- 회사 Windows, 집 macOS. Doom Emacs가 주력. Claude Code를 Emacs 패키지 agent-shell(ACP)로 씀. Windows에서는 Git Bash 도구
- 전역 지시 `~/.claude/CLAUDE.md`, 숙련도 `~/.claude/CLAUDE.local.md`
- 스킬은 dotfiles `claude/skills/`, Emacs 설정은 dotfiles `doom.d/config.org`

## 파트 파일 형식

- `=== U<n> [YYYY-MM-DD HH:MM] 사용자` - 사용자 발언
- `[시각] 에이전트` - 에이전트 발언
- `[시각] 에이전트 도구 <이름>: ...` - 도구 호출 한 줄
- `[시각] 도구 결과(Bash|오류)` - Bash 결과(앞뒤 15줄), 오류 결과
- Read 결과, compact 요약은 빠져 있다

## 절차

1. 세션마다 파트 파일을 **처음부터 끝까지** Read한다. 크면 offset을 옮겨 끝까지 읽는다.
2. 마찰을 찾아 아래 범주 하나에 넣는다. 사용자 정정("왜 이렇게", "번복", "아니라")은 원인을 따져 범주를 고른다.
3. 알려진 패턴이 있으면, 해당하는 마찰은 횟수와 사례만 적고 그 패턴 이름을 `알려진:` 으로 붙인다. 시간은 **목록에 없는 새 패턴**을 찾는 데 쓴다.
4. 사실만 적는다. 근거 없는 추측은 금지. 사소한 1회성도 적되 비용을 낮게 표시한다.
5. 코드/파일 위치는 절대 경로로 적는다.

## 범주

retro 범주 (에이전트 환경):
- Navigation: 필요한 파일/정보를 찾는 데 오래 걸림, 숨은 파일 간 의존
- Automated checks: 자동 검사(린트, 테스트, hook)로 잡을 수 있었던 실수
- Coding standards: 리뷰 규칙으로 잡아야 할 판단 문제. 기계적 패턴이면 Automated checks로
- Global AGENTS.md: CLAUDE.md 등 상시 지시가 지켜지지 않거나 충돌, 다른 곳으로 옮길 지시
- Tool economy: 비싼/낭비성 도구 호출, 반복 실패 후 재시도, 토큰 비효율
- No-ops: 효과 없는 지시, 의미 없는 왕복
- Information access: 에이전트가 필요한 정보(로그, 에디터 상태, 외부 서비스)에 접근 못 함

Emacs/사람 쪽 범주:
- E1 수동 컨텍스트 전달: 사용자가 `파일:줄`, 선택 영역, 에러 로그, 이전 답변 인용을 손으로 붙여넣음
- E2 결과 확인 마찰: 에이전트 결과를 사용자가 열어 보고 문제를 발견 (형식 깨짐, 줄 끝, 인코딩, 잘못된 위치)
- E3 세션 간 반복 지시: 같은 지시를 반복 (세션 안 반복도 기록 - 메인이 세션 간으로 합친다)
- E4 harness 결함: 중단, 권한 거부, 도구 오류, 깨진 한글, agent-shell/ACP 문제로 흐름이 끊김

## 고칠 곳 (항목마다 하나 이상)

- `claude-config` - CLAUDE.md, settings.json, 스킬 문서
- `hooks` - Claude Code hooks
- `agent-shell` - Emacs agent-shell elisp
- `emacs-mcp` - 에이전트가 실행 중인 Emacs를 조회하는 도구
- `repo-check` - 저장소 검사, 설정 (.gitattributes, .gitignore, 테스트, CI)
- `script` - 보조 스크립트

## 반환 형식

세션마다:

```
세션: <id8> <프로젝트> <주제 한 줄>
- [범주] [고칠 곳] <마찰 한 줄 요약>   (알려진: <패턴 이름> | 신규)
  횟수: <이 세션 안에서 몇 번>
  비용: <사람 시간 | 토큰 | 재작업 | 흐름 끊김 | 보안> - <근거 한 줄>
  원인: <왜 생겼나 한 줄>
  사례: <HH:MM> <사용자|에이전트|도구> "<원문 짧은 인용>"   (최대 2개)
  제안: <고칠 곳>: <무엇을>   (방법이 여럿이면 줄을 나눠 모두)
```

- 마찰이 없으면 `- 없음`.
- 비밀값(token, key, password)이 출력/명령에 남은 것을 보면 비용을 `보안`으로 적는다. 인용에는 값을 그대로 옮기지 않고 `...`로 가린다.
- 마지막에 "세션 공통 관찰" 1-3줄 (있으면).
